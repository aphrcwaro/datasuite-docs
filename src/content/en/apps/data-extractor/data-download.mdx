# Downloading data

Once login, metadata retrieval, and mapping are complete, the extractor can begin data download.
Instead of relying on a single large DHIS2 request, the extractor is designed to handle extraction in smaller and more manageable batches.
This approach lowers the risk of timeouts for large download requests, thus reducing the chances of incomplete downloads.

<Callout type="warning">

**Large extractions still need planning:**

- Even with caching and chunked processing, very large downloads may take time depending on server performance, user permissions, internet stability, and the size of the requested organization unit and period ranges.

</Callout>

## Download steps

<Steps>

### [Complete and save your mapping](/en/apps/data-extractor/mapping)

### Go to the Downloads Manager and click **+ New Download Task**

![Downloads Manager with the New Download Task button](/images/extractor_downloading.jpg)

### Configure the download parameters

Select the mapping (**Mapping Configuration**, in case you have multiple mappings), the period (**Date Range**, start and end dates), the **Frequency** (monthly or yearly; shown for Custom mappings only), the **Admin Level** and, optionally, a **Sub-region** to limit the download to one area, then click **Start Download**.

![Configure Download Task dialog](/images/extractor_download_config.jpg)

<Callout type="info">

**Countdown download configuration:**

- **Date Range:** use the last five years (for example, January 1st 2020 to December 31st 2025).
- **Admin Level:** use Level 3.

</Callout>

### Export the data

When the task is complete, it moves to **Recent History**. In its **Actions** column, click **Export to Excel** to save the workbook that the [RMNCAH and Vaxx apps](/en/apps/countdown/getting-started) load (sheets `Service_data`, `Population_data`, `Reporting_completeness` and `Admin_data`), or **Export to JSON**. A failed task can be restarted with **Retry Download**. On a DHIS2 server that uses the Ethiopian calendar, **Excel labels** chooses Ethiopic or Gregorian period labels for the Excel file.

</Steps>

Caching is not only useful for metadata. It also helps the extractor preserve progress and reduce unnecessary repeated work where extraction tasks are interrupted or revisited.

This improves reliability in practical field conditions, especially when:

- internet connectivity is unstable,
- DHIS2 response times vary,
- analysts need to rerun the same extract after refining mappings,
- teams want a reproducible process with less manual repetition.

<Callout type="info">

**Tip:** If you are testing mappings, validate the metadata and structure first using a smaller extraction range before launching a full national, multi-year download.

</Callout>
